# Cohort 3 Track B Submission Draft

## Recommended approach

Add a visible, branded UnvibeCode change-review loop. Compare a branch or commit with a saved baseline, show which workflows and code evidence changed, and share a compact UnvibeCode summary in a pull request.

## Why this supports repeat use

- My Flask trial took me through the Business Workflow Map, Connected Code Map, Business Risk Findings, LLM Context, and repository context export. A changed-code review creates a reason to return when a familiar repository changes.
- Existing docs explain focused context and full repository export for AI use. A source-linked handoff with scope and provenance can reduce manual preparation while keeping UnvibeCode visible when an assistant is involved.
- A PR summary linking to changed workflow evidence encourages developers to verify the change instead of treating assistant output as a black box.

## Implementation plan

Start with saved baseline metadata and a changed-file review linked to existing workflow, graph, and risk evidence; generate a branded PR-ready summary and assistant-ready focused context index. Pilot on Flask and several public repositories, measuring second-review conversion, time-to-answer, export reuse, and PR link opens.
